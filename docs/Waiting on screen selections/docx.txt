@P@ITM GOOGLE STITCH PROMPT BOOK
@P@How to Use This Prompt Book
@P@Google Stitch produces stronger results when it receives one focused screen request at a time inside the same project. The sequence below establishes the system first, then creates public, consultant and client experiences.
@P@Start one new Stitch project and paste Prompt 01 to establish the visual system.
@P@Generate the shared public shell and dashboard shell before requesting individual pages.
@P@Paste one screen prompt at a time. Keep the instruction “continue the same project” intact.
@P@Generate desktop first, then ask Stitch for the responsive mobile version of the same screen.
@P@For a weak result, revise only the problem area: spacing, hierarchy, mobile stacking or component density.
@P@Export approved screens and component references for the development team. Stitch designs the interface; the PRD remains the source of truth for business rules.
@P@CRITICAL RULE
@P@Do not ask Stitch to invent official certificates, authority logos, statutory fees, processing guarantees or client data. Use realistic placeholders and neutral document previews.

@P@Prompt 01 - Master visual system
@P@Use for: Creating the design language before individual screens
@P@COPY INTO GOOGLE STITCH
@P@Create a complete visual direction for “ITM Business Solutions,” a premium Zimbabwean company-registration and compliance consultancy. Use deep navy #152A45 as the authority colour, teal blue #247BA0 for primary actions, warm off-white #F4F7F9 for page backgrounds and restrained gold #D79B2E for small highlights only. Use a clean modern sans-serif such as Inter or Manrope. The interface must feel trustworthy, calm, precise and premium rather than like a government portal or generic template.Define reusable tokens for type scale, 8-point spacing, 12-column desktop grid, mobile grid, 18px card radius, input styles, buttons, badges, progress steps, data tables, empty states and alert levels. Use generous whitespace, subtle borders, soft low-elevation shadows and limited translucent panels. Keep body text highly readable. Avoid neon colours, heavy gradients, excessive glassmorphism, giant decorative icons, fake official seals, flags and clutter.Design for desktop, tablet and mobile. Public pages use a maximum content width around 1200px. Dashboards use a fixed desktop sidebar and compact mobile navigation. Establish accessible colour contrast, visible focus states and plain-language status labels. Show the design system as a coherent component reference board that later screens can follow.

@P@Before accepting a Stitch screen, confirm the following. A beautiful screen that breaks the commercial or permission model is not approved.
@P@•  The screen follows the approved navy, teal, off-white and restrained gold palette.

@P@•  No authority approval, deadline, fee or processing time is invented.
@P@•  No official logo, fake certificate, fake seal or client identity data appears.
@P@•  Mobile layouts work without horizontal scrolling or tiny controls.
@P@•  Empty, loading, error, permission-limited and action-required states are designed.
@P@•  SEO pages contain useful readable content rather than decorative cards only.
@P@•  The PRD remains the source of truth for workflow, permissions, security and data behaviour.
